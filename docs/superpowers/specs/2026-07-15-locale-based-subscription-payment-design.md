# 按页面语言分流订阅支付设计

## 背景

订阅页当前同时展示美元和人民币价格。用户选择套餐后，还需要在弹窗中选择 Creem 国际支付或微信支付。新的业务规则要求页面语言直接决定支付渠道：中文使用微信支付，英文使用美元支付。

## 目标

- 中文订阅页只展示人民币价格，只能创建微信支付订单。
- 英文订阅页只展示美元价格，只能创建 Creem Checkout。
- 点击付费套餐后直接进入对应支付流程，不再展示支付方式选择步骤。
- 后端同步校验语言与渠道，拒绝不匹配的请求。
- 保留现有登录保护、订阅资格检查、二维码轮询、Creem 跳转和已有订阅管理行为。

## 非目标

- 不调整套餐价格数值、额度或月付/年付定义。
- 不更改 Creem 产品 ID、微信商户配置或支付回调协议。
- 不删除当前未被新主流程使用、但仍被旧组件引用的支付方式组件。
- 不改变历史支付记录的币种展示。

## 支付渠道规则

| 页面语言 | 展示币种 | 支付渠道 | API |
| --- | --- | --- | --- |
| 中文 `zh` | CNY / `¥` | 微信支付 | `/api/billing/wechat-pay` |
| 英文 `en` | USD / `$` | Creem | `/api/billing/subscribe` |

页面语言来自 URL：无 `/en` 前缀为中文，`/en/...` 为英文。浏览器语言、地理位置和本地存储不参与支付渠道判断。

## 前端流程

### 套餐展示

`PlanComparison` 只渲染当前语言对应的一种价格：

- 中文：`¥9`、`¥99` 等 CNY 文案。
- 英文：`$9`、`$99` 等 USD 文案。
- 免费方案分别显示 `¥0` 或 `$0`。

价格数值继续来自现有 `PRICES`，本次不改变价格配置。

### 点击付费套餐

用户未登录时，继续跳转到当前语言的登录页。

用户已登录且有购买资格时：

1. 根据 `locale` 得到唯一支付方式：`zh → wechat_pay`，`en → creem`。
2. 按钮进入 loading 状态，防止重复请求。
3. 中文调用微信支付接口；成功后显示现有二维码组件。
4. 英文调用 Creem 接口；验证返回 HTTPS URL 后跳转 Checkout。
5. 失败时在套餐区域显示当前语言的支付错误，并允许重试。

支付方式选择弹窗从当前订阅主流程移除。相关旧组件不因本次改动被主动删除。

### 续费与已有订阅

- 微信支付是手动续费，续费入口只在中文页面显示并直接创建微信订单。
- 英文页面不提供微信续费入口；用户可切换到中文页面进行微信续费。
- 已有 Creem 订阅的管理入口保持 provider 驱动，不因页面语言被隐藏或改写。
- 当前已有付费订阅时，原有防止重复购买的规则保持不变。

## API 契约

### Creem Checkout

`POST /api/billing/subscribe` 请求保持：

```json
{ "plan": "pro", "interval": "monthly", "locale": "en" }
```

接口只接受 `locale: "en"`。合法结构但 locale 为 `zh` 时返回 HTTP 400 和稳定错误码：

```json
{ "error": "PAYMENT_METHOD_LOCALE_MISMATCH" }
```

原有字段白名单、登录、邮箱、功能开关和购买资格检查保持不变。

### 微信支付

`POST /api/billing/wechat-pay` 请求从两个字段扩展为三个字段：

```json
{ "plan": "pro", "interval": "monthly", "locale": "zh" }
```

接口只接受 `locale: "zh"`。合法结构但 locale 为 `en` 时返回 HTTP 400 和同一稳定错误码 `PAYMENT_METHOD_LOCALE_MISMATCH`。

缺字段、多余字段、无效套餐、无效周期或无效 locale 继续作为字段校验失败处理，不创建订单。

## 错误与安全

- 客户端不能通过传入支付方式选择渠道；渠道只由 `locale` 派生。
- 后端在调用购买资格检查或第三方支付前完成 locale 校验。
- 渠道不匹配不创建 Creem Checkout 或微信订单。
- 用户界面不展示后端内部错误细节，继续使用本地化通用支付错误。
- Creem 返回 URL 仍必须为 HTTPS。

## 组件边界

- `SubscriptionContent`：根据 locale 选择 API、构造请求并处理渠道响应。
- `PlanComparison`：展示单一币种、管理直接支付的 pending/loading/error 和微信二维码状态。
- `CurrentPlan`：仅在中文页面暴露微信续费动作；Creem 管理动作保持现状。
- API route：执行字段与 locale/渠道一致性校验。

不引入新的全局支付状态或支付抽象层。

## 测试策略

### 单元和 API 测试

- `zh` 派生 `wechat_pay`，`en` 派生 `creem`。
- 中文价格仅为 CNY 格式，英文价格仅为 USD 格式。
- Creem 拒绝 `locale: "zh"`，且不调用购买资格或 Checkout 创建。
- 微信接口拒绝 `locale: "en"`，且不调用购买资格或订单创建。
- 微信接口要求且只接受三个请求字段。

### 浏览器测试

- 中文页面不显示美元价格、Creem 选项或支付方式选择器。
- 英文页面不显示人民币价格、微信选项或支付方式选择器。
- 中文点击套餐直接提交微信请求并展示二维码。
- 英文点击套餐直接提交 Creem 请求并跳转 HTTPS Checkout。
- 未登录状态继续进入当前语言登录页。
- 微信续费只在中文页面可操作。
- 现有订阅状态、支付历史、二维码轮询与取消、Creem 管理动作不回归。

## 验收标准

- 页面语言是支付渠道的唯一前端选择依据。
- 主流程没有支付方式选择步骤。
- 前后端都拒绝语言与支付渠道不一致的行为。
- 中文和英文订阅流程分别完整通过微信和美元支付测试。
- 单元测试、计费 E2E、lint 和生产构建通过。
